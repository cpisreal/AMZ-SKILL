# 转化路径报告 → 广告预算分配

一张转化路径报告能回答别的报表回答不了的问题：**钱是沿着什么顺序进来的，下一步该往哪加。**

这个 skill 把它算成六块结构 + 一组可执行判断。

## 什么时候用

- 拿到 Conversion Path Report（xlsx / csv），想知道该怎么读
- 要判断 SP、SB、SD、DSP 的预算怎么分
- 想做「打了 A 之后该多打 B」这类接力判断
- 想知道自己的结构是不是过度依赖某一条路径

## 前置：报表怎么导

广告后台 → 报表中心（Reports）→ 报表类型选 **Conversion path**。
三个设置决定数据能不能用：

| 设置 | 选什么 | 为什么 |
|---|---|---|
| 时间范围 | **30 天，不要 7 天** | 长路径要两三周才走完，7 天窗口会把它们整条切掉，结论会变成「上层广告没用」 |
| 聚合维度 | **按转化路径** | 按广告活动分组的报表看不到组合 |
| 格式 | xlsx 或 csv 都行 | 数字是原始精度 |

导出来一行 = 一条路径在整段窗口的**汇总**（不是一笔订单）。298 条路径就是 298 行。

## 快速开始

```bash
pip install openpyxl          # 只读 xlsx 需要；用 csv 可跳过

python scripts/analyze_conversion_path.py 报表.xlsx
python scripts/analyze_conversion_path.py 报表.xlsx --top 15 --out 结果.xlsx
```

参数：
- `--top N` 明细显示前 N 条（默认 10）
- `--out 文件.xlsx` 同时导出 7 个表（概览/首触点/转移/分层/产品覆盖/单点路径/判断）

只依赖标准库 + openpyxl，不联网、不上传、不读报表以外的任何东西。

## 六块输出怎么读

**一 · 集中度** —— 前 1 / 2 / 4 条路径各占多少，累计到 50%、80% 需要几条，长尾多少条。
用法：找到你的「管理边界」。边界以内逐条分析，边界以外只监控合计占比，不要试图优化单条。

**二 · 首触点（谁在开场）** —— 每个广告产品作为第一个触点的路径数、销售额、客单价。
用法：这是预算的第一顺位依据。开场占比高、客单价不掉的那个，是基本盘。

**三 · A → B 转移** —— 首触点是 A、第二个触点是 B 的组合，各自的销售额、占比、客单价。
这是本 skill 最有价值的一块。它直接回答「A 跑起来之后，下一笔钱给谁」。

**四 · 触点数量分层** —— 1 / 2 / 3 / 4 / 5+ 触点各自的路径数、销售占比、客单价、新客占比。
用法：客单价通常随触点增加而上升，新客占比同时下降。这说明长链路是老客在反复评估，不是新客在层层递进。

**五 · 产品覆盖 vs 销售** —— 每个广告产品出现在多少比例的路径里（覆盖率）、带来多少比例的销售、自己开场占多少。
「覆盖/销售」这个比值是关键：比值大 = 到处都在但产出低。

**六 · 判断与动作** —— 把上面五块翻成几句可执行的话。

## 判断口径（本 skill 的核心规则）

三类广告，判据不同：

| 类型 | 判据 | 动作 |
|---|---|---|
| **主力** | 销售占比高，且自己开场占比也高 | 不报。按护栏管理，不做结构性调整 |
| **助攻** | 销售占比 ≥ 10%，但「覆盖率 − 开场占比」≥ 15pt | 按覆盖考核，不用末次点击 ROI 判去留 |
| **伴随** | 销售占比 < 10%，但覆盖率 ≥ 15% | 按维持给预算，不按拉动成交给 |

阈值都在脚本顶部 `TH` 字典里，可以按自己账号改。它们是经验值，不是平台标准。

判定逻辑写在 `references/judgment-rules.md`，含每条规则的依据和反例。

## 三条硬前提

**路径不等于因果。** 一条路径里有 DSP，只说明这个买家中途被 DSP 触达过，不说明 DSP 促成了它。要证明因果只有一条路：关掉一部分看总销售掉多少。

**末次点击会系统性低估上层广告。** 最后一步几乎总是商品推广（买家在搜索结果页点商品），所以 DSP、品牌视频的功劳都被记在 SP 账上。「助攻」这一栏就是为了把这些功劳捞回来。

**一份报表只反映一种归因。** 路径是唯一归因（一笔订单只落在一条路径），不是份额分摊。两种口径的报表数字不能混着用。

## 别用它做的事

- **不用来算日销**：一行是整段窗口的汇总，没有日粒度
- **不用来比绝对金额**：每行日期跨度不同，跨度长的天然更大，要比结构比例
- **不直接给预算百分比**：报表能给你分配结构，给不了「SP 占 40%」这种绝对比例，那得结合你自己的 ACoS 和库存定
- **不做因果证明**：只能说明参与了，不能说明促成了

## 坑

**20 列里 11 列是频次列**（`... frequency`）。第一次读先遮住，它们回答的是「平均被看了几次」，跟路径结构是两个问题。

**有两个列名一模一样**，都叫 `Sponsored Display frequency`。Excel 打开会改名，但脚本按列名取数会永远拿到第一个。本脚本不依赖频次列，所以不受影响；你自己写脚本时要按位置认。

**xlsx 的 `<dimension>` 标签可能不准**。用 openpyxl 的 `read_only=True` 会把列截断成 1 列，看着像「找不到 Conversion path 列」。本脚本已关掉 read_only。

**路径写法有多种形态**：`(Sponsored Display)` 带括号、`Display (Amazon DSP)` 与 `Amazon DSP` 并存。脚本用 `NORM` 字典归一到粗粒度，想保留细分就改这个字典。

**币种**：金额符号按报表 Currency 列自动加，认不出的币种只显示数字不瞎猜。
