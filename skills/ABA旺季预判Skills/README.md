# ABA 旺季预判 Skills

**解决的问题**：让「一个品类什么时候起量、什么时候见顶、什么时候该撤」这件事，
从「凭经验猜」变成**一条命令跑出来的三个时间点**。

你手上只要有 **ABA 热搜词周报**（亚马逊后台 → 品牌分析 → 搜索词报告，按周下载），
就能拿到：这个品类由哪些**属性**构成、每类属性每周涨多少、**进场点 / 加码点 / 撤退点**分别在哪一周。

配套文章：《[附送Skills] 用ABA看产品属性加速度，预判旺季起量时间》

---

## 30 秒试跑（不需要任何数据、不需要 key）

```bash
pip install -r requirements.txt
python run.py demo
```

它会自己造 12 周演示数据 → 跑完五步 → 在 `demo/out/` 出报告。
演示数据里**故意埋了三个坑**（`womens` 被 `men` 词根误伤、`gift` 属性整季为 0、
一个属性早衰一个属性慢衰减），你一眼能看到每一步挡掉了什么。

## 用自己的数据

```bash
# 0) 把 ABA 周报 CSV 放进一个目录，文件名要带 YYYY_MM_DD
#    如 US_Top_Search_Terms_Simple_Week_2025_11_08.csv

# 1) 建议先转 parquet 缓存（第 2 遍起快一个量级）
python run.py cache --csv-dir ./aba --cache-dir ./.cache

# 2) 一条命令出结果：品类词 = 必须同时含 christmas 和 pajama
python run.py all --csv-dir ./aba --cache-dir ./.cache \
                  --must christmas,pajama --rules rules/pajama_winter.json --out ./out
```

产出（`out/` 下）：

| 文件 | 里面是什么 |
|---|---|
| `1_种子ASIN.csv` | 品类里最中心的 N 个产品，按「被多少个相关词命中」排序 |
| `2_关联词表.csv` | 从这批种子 ASIN 反查出来的全部搜索词（去重） |
| `3_属性周矩阵.csv` | 属性 × 周 的词数矩阵 |
| `4_加速度表.csv` | 每个属性/词根的每周环比增量 + 三个时间点标注 |
| `报告.md` | 结论汇总：主轴词根、零需求属性、三个时间点、属性节奏对比 |

## 五步是怎么走的

| 步 | 做什么 | 关键口径 |
|---|---|---|
| **1 数据准备** | 周文件读进 DuckDB | 只留 5 列（列裁剪）；**CSV 第一行是元数据，必须 skip=1** |
| **2 找种子 ASIN** | 品类词模糊搜索 → 命中行里的 Top Clicked ASIN → 按命中词数排序取 top N | 用「命中词数」而不是「搜索频率」，找的是**流量中心产品** |
| **3 反查关联词** | 全量数据里「Top Clicked ASIN ∈ 种子」的所有行 → Search Term 去重 | 这一步是「从 ASIN 找词」，得到真实消费者在搜什么 |
| **4 词根归属性** | 词根匹配把散词聚成属性 | **词根要用空格包裹**，否则 `men` 会误伤 `womens` |
| **5 加速度 + 周统计** | 每周词数 → 环比增量（一阶差分）→ 三个时间点 | 词量是积分、加速度是导数；**进场看导数，不看积分** |

## 三个时间点怎么读

- **进场点 = 加速度见顶那一周**（增长最快、还在加速）
- **加码点 = 词量见顶那一周**（量最大，但加速度已经在下滑）
- **撤退点 = 加速度断崖那一周**（环比大幅转负，收预算、撤排名、清库存）

一句话：**加速度见顶进场，词量见顶加码，加速度断崖撤退。**

## 常用参数

| 参数 | 说明 |
|---|---|
| `--csv-dir` | ABA 周报 CSV 所在目录 |
| `--pattern` | 文件名模板，默认 `US_Top_Search_Terms_Simple_Week_{week}.csv` |
| `--must` | 品类词，逗号分隔，**必须全部同时命中**（如 `christmas,pajama`） |
| `--top` | 种子 ASIN 个数，默认 10 |
| `--rules` | 属性规则包（内置 `rules/pajama_winter.json`，换品类复制改词根） |
| `--week-from` / `--week-to` | 只分析某段周次，如 `--week-from 2025_10_18 --week-to 2026_01_03` |
| `--threads` | DuckDB 线程数，默认 4 |

## 换品类怎么改

复制 `rules/pajama_winter.json`，只改里面三块：

1. `label`：品类名
2. `attributes`：属性 → 词根列表（你的品类由哪些维度构成）
3. `must_terms`（可选）：默认品类词

代码一行都不用动。

## 四个必踩的坑（包里已经处理，但你要知道为什么）

1. **20 GB 的 CSV 别用 Pandas 硬读** —— 会 OOM。用 DuckDB + 列裁剪，只读 5 列，12 个文件十几秒。
2. **ABA 导出的 CSV 第一行不是表头** —— 是一行 `Reporting Range=...` 元数据，不 `skip=1` 就整列错位。
3. **别把「词量顶点」当「进场信号」** —— 词量最高时加速度已经在降了，这是旺季踩空的头号原因。
4. **词根匹配要空格包裹** —— `men` 直接子串匹配会把 `womens`（女士）误伤成男士。

另：算环比时第一周没有「上周」可比，**加速度图比词量图少一个点**（12 周 → 11 个增量），别对错周。
