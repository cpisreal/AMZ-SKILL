# ABA 自动词库 Skills

> 给你 ABA 数据 + 一组 ASIN，一键产出「高相关关键词词表」。
> **词库不是手动堆出来的，是「ABA 数据反向命中 ASIN + 决策模型 Jev 打分」自动挖出来的。**

---

## 它解决什么

选词最贵的不是「找词」，是**判相关度**。

- **正向捞词有天花板**：你只能看到自己投过的词，看不到「你没投过、但竞品正在吃的词」。
- **人肉判相关度最贵还最容易出错**：一个台面制冰机的竞品单周命中 360 个词，一个词一个词判到怀疑人生；
  更要命的是标准会漂 —— 同一个词，今天标「相关」，下周再看到又标「不相关」，词库越攒越乱。

这套工具换了个方向：**反向命中**。ABA 热搜词报告里，每个搜索词都带三列「点击最多的商品 #1/#2/#3」ASIN。
把你的竞品 ASIN 丢进去，就能捞出「整个类目里真实买家在搜、并且搜完点进了这些竞品」的词 ——
绕开了正向捞词的天花板。再用 **Jev**（决策模型，不是生成式大模型）批量判相关度 + 分类，人只做最后一眼抽验。

## 3 分钟先跑通（不需要任何 key）

```bash
cd ABA自动词库Skills
pip install -r requirements.txt

python demo/make_demo_aba.py          # 造一份演示用 ABA 数据（合成数据）
python run.py \
  --aba-dir ./demo/aba \
  --asins   ./demo/asins.txt \
  --target  B0DEMOTGT1 \
  --listing-json ./demo/listing.json \
  --provider mock \
  --out ./成品_演示词表.xlsx
```

跑完你会得到一张 `成品_演示词表.xlsx`。**`--provider mock` 是用规则近似打分，不是 Jev**，
只用来确认环境和流程没问题。正式用请看下面。

## 输出的词表怎么读

| 列 | 含义 | 怎么用 |
|:--|:--|:--|
| **搜索词** | 反向命中的词 | — |
| **相关度分** | Jev 给的 1–10 分 | **≥8 分**直接建活动；6–8 分分层控成本；<6 分放观察池 |
| **词分类** | 6 类：品类词 / 自有品牌词 / 竞品品牌词 / 属性规格词 / 场景用途词 / 其他长尾 | 见表下方「打法」 |
| **最近排名** | 命中周里**最新一周**的搜索频率排名 | 跟历史最佳一对比，就知道这个词是在起量还是在掉 |
| **历史最佳排名** | 所有周里的最好排名 | 最近排名 ≫ 历史最佳 = 在掉；最近 ≈ 最佳 = 正热 |
| **命中ASIN数** | 有多少个目标 ASIN 出现在这个词下 | 命中越多 = 越多竞品在吃这个词，越是必打 |
| **点击份额** | 最新一周命中的竞品在该词下吃掉的 click share | 份额越高越难抢，但抢下来的收益也越大 |
| **把握度** | Jev 对「这个分」的置信度 | **<60% 建议人工抽验**，≥90% 可以闭眼用 |
| **你会怎么用** | 按分类自动给出的打法建议 | — |

**6 类词对应的打法**（表里已自动填好）：

| 词分类 | 打法 |
|:--|:--|
| 品类词 | **主力投放** |
| 自有品牌词 | **守品牌**（防止竞品截流） |
| 竞品品牌词 | **否定词** / 或单独开活动打拦截 |
| 属性规格词 | 长尾拓量 |
| 场景用途词 | 长尾拓量 |
| 其他长尾 | 低优先，观察 |

表格自动上色：**绿底 = 强相关（≥8 分）**，**红底 = 竞品品牌词**（拿去当否定词候选），
黄色 = 中相关。另外一张 `运行摘要` sheet 会告诉你总词数、强相关数、竞品品牌词数、
以及**有多少个低把握词需要你人工抽验**。

## 四步流水线在做什么

```
① DuckDB 装载  →  ② ASIN 反向命中  →  ③ 爬 Listing  →  ④ Jev 打分 + 分类  →  Excel
```

**① 用 DuckDB 把 ABA 数据装进去**
一周一个 CSV 就 270 万行、1.3–2GB，十二周 3200 万行。Excel 打开直接死机，pandas 也吃满内存。
DuckDB 是列式数据库，本地一个文件就能跑，查 270 万行是秒级的事。选对工具，后面每一步才不会卡。

**② ASIN 反向命中搜索词**
找出所有「Top Clicked Product #1/#2/#3 三列里出现过这些竞品 ASIN」的词，同时把口径一起算出来。
关键口径：**「最近一次排名」和「历史最佳排名」是两回事** —— 排名是波动的，它的涨跌本身就是选词信号。

**③ 爬目标 ASIN 的 Listing**
抓回标题、五点描述、描述、品牌。这堆文本就是第 4 步的「标准答案」。
为什么一定要爬、不能凭 ASIN 号猜？因为 Jev 判相关度靠的是拿搜索词跟商品的**文字描述**比 ——
`bullet ice maker`（子弹冰）和 `nugget ice maker`（冰珠）只差一个词，但冰型完全不同。

**④ Jev 打分 + 分类**
把 Listing 当「参考物」只放一次，一批词当成一批**独立的问题**一次性丢给 Jev（它并行判定，
加问题几乎不增加耗时）。每个词拿回两个结果：**相关度分（1–10）** + **词分类（6 类）**。
为什么用 1–10 分而不是是/否？因为词的价值是分层的：9 分和 6 分都叫「相关」，但投放力度天差地别。

> **为什么不用生成式大模型**：生成式是「一个字一个字往外蹦」，给几百个词打分它会 ① 慢（每个词排队等完整生成）
> ② 贵（每个词走一遍完整推理）③ 会幻觉（同一个词问两次给两个答案）。
> Jev 是 TypeSafe 的 System One 决策模型，走的是 **Decisions API**（不是 chat 接口），
> 返回**类型化的概率答案**，结构上编不了；速度是 70–500ms/请求，成本约 $0.042/百万输入 token（输出免费）。
> 它给的还是「概率」不是「结论」—— 同样是 9 分，60% 把握和 99% 把握是两个完全不同的信号。

## 三个坑（照抄能省你半天）

**坑一：ABA 的 CSV 第一行不是表头。**
每个文件第一行是一段元数据 `Reporting Range=...`，真正的表头在**第二行**。
不 skip 掉这一行，整列错位、后面命中全废。本工具会自动跳过，并把区间解析成「周标签」。

**坑二：爬 Listing 时抓到的价格可能是别的币种。**
如果你的网络走海外节点，price 字段可能抓到新加坡元（S$）这种。它跟关键词相关度无关，
但别拿它去做定价判断 —— 那个要单独去美国站核。本工具会检测并给出告警。

**坑三：Jev 一次别塞太多词。**
它一次能处理的问题量有上限。**本文用 60 个词/批作为安全值**，塞多了直接报错 ——
不是模型笨，是你贪了。老老实实分批，多跑几次反而更稳（用 `--batch` 调）。

## 边界（很重要）

**这套工具做的是「选词」这一步，出的是「词表」，不是「直接开投」的结论。**

Jev 的分再准，也只是**相关度**的判断。最后还得你结合转化数据、竞价、预算去做投放决策。
它替代的是「人肉筛词的体力活」，不是「你作为操盘手的判断力」。

## 常见问题

**Q：跑 Listing 抓取被验证码拦了怎么办？**
加 `--proxy http://127.0.0.1:7890` 走干净出口；或者自己抓好后用 `--listing-json` 喂进来。
JSON 的格式参照 `demo/listing.json`（字段：`asin/title/brand/category/bullets/description`）。

**Q：类目 / BSR / 价格是空的？**
Amazon 对不同客户端会返回不同版本的页面，精简版里没有面包屑和价格结构化数据。
这些字段**不影响打分**（打分只看标题、五点、品牌），空着可以直接忽略。

**Q：ASIN 一个词都没命中？**
先看控制台的告警：工具会列出「一个词都没命中的 ASIN」。常见原因：ASIN 写错、
站点选错（`--market`）、或者 ABA 报告没导入成功（看第 1 步的行数）。

**Q：想先不花钱看看效果？**
`--provider mock` 用规则近似打分，能验证流程但**不能当结论**。

### 参数速查

| 参数 | 说明 |
|:--|:--|
| `--aba-dir` | ABA 报告所在目录（会递归找 .csv/.txt） |
| `--db` | DuckDB 库文件，默认 `./aba.duckdb`（复用可跳过重复导入） |
| `--rebuild` | 清库重建 |
| `--asins` | 竞品 ASIN：文件路径 或 逗号分隔 |
| `--target` | 目标 ASIN（爬它的 Listing 当打分基准） |
| `--market` | 站点后缀：`com` / `co.uk` / `de` / `co.jp` … |
| `--proxy` | 抓 Listing 用的代理 |
| `--listing-json` | 直接喂已抓好的 Listing JSON，跳过爬取 |
| `--provider` | `openrouter`（默认）/ `typesafe` / `mock` |
| `--api-key` | 也可以直接传 key，不写 .env |
| `--batch` | 每批词数，默认 60 |
| `--max-words` | 最多处理多少个词（先小批量试） |
| `--out` / `--json-out` | 输出 xlsx / 附带 JSON |
